## 3. 문제 · 해결 과정

| 문제 | 원인 · 해결 |
|---|---|
| 노션 10주차가 「여유 6.8 % 부족」 전제로 쓰여 있음 | 6.8 % 는 8주차 「PDR 52 기준」 값 — 팀장 11/19 회신으로 기준 자체가 바뀜. 새 정의(필요 대비, 정격 기준)로 다시 계산하면 3 kg 에서 이미 통과 → 과제는 그대로 하되 「결정이 필요 없다」는 것을 m_max · r_max 숫자로 보이고, 두 방안은 플래그로만 구현 |
| 검증 ③ 회귀 값이 42.66 으로 나옴(기준 42.91) | 15° 격자 시작점을 관절 하한으로 잡아 0 · ±90° 가 빠짐 → validate_model 과 같이 15° 배수 격자로 고쳐 42.91 일치 |
| 3,000 무작위 자세 최대(48.69)가 정확한 수평 자세(48.85)보다 0.3 % 작음 | 무작위 표본이 최악점을 정확히 못 짚음. 팀장 승인 값과 맞추려 판정은 48.69 유지, md 에 주의로 적고 CDR 동결 때 국소 최적화로 고정하기로 함(여유 48.6 %, m_max 4.86 kg — 결론 같음) |
| 「베이스 가속 추가분」 방법이 두 가지 | 8주차 방법(정적 최악 + 다른 자세의 가속 최대분) 48.69 vs 같은 자세에서 동시 계산 46.86 → 8주차 방법이 3.9 % 보수적. 판정은 보수적인 쪽 유지, 참고 열로 같이 냄 |
| build_v1 · MJCF 는 박종진 저장소 | 원본을 건드리지 않고 `build/` 사본에서 `B1_A2_CASE` 로 빌드 → params.yaml 의 case 한 줄이 MJCF 까지 반영. 박종진 build_v1 에 `--config` 인자를 넣을지는 박종진과 합의 |

## 5. 구술 대비 (11/26 목)

- Q1 허용 짐 질량을 선형식으로 역산할 수 있는 이유와 깨지는 조건 — 같은 자세에서 정적 토크 τ = τ₀(q) + m · g · J_zᵀ(q) 는 m 의 1차식 → m = (정격/1.2 − τ₀)/(g r). 최악 자세(팔 수평)가 짐 0 ~ 15 kg 에서 그대로라 선형식 4.89 = 스윕 4.88 kg. 깨지는 조건: 가감속(M(q) q̈ 에 짐 관성, 빠른 궤적이면 최악 자세가 바뀜 — 6주차 뻗기 0.6 s 는 +33 %), 접촉 · 충격(놓을 때 튐, 파지 중 미끄러짐으로 r 변화), 최악 자세가 바뀌는 큰 짐. **내 의견**: 판정은 정적 + 설계 가속까지 선형식으로 하고, 동작 시간 제한(3 kg 팔 동작 ≥ 2.0 s, 7주차 회신)을 같이 걸어 동적 항을 묶어 둔다
- Q2 「필요 대비」 vs 「정격 대비」 20 % — 필요 대비 20 % ⇔ 정격 ≥ 1.2 × 필요, 정격 대비 20 % ⇔ 필요 ≤ 0.8 × 정격(= 정격 ≥ 1.25 × 필요). 같은 「20 %」 가 필요 대비로 환산하면 20 % vs 25 %(5 %p 차), 정격 대비로는 16.7 % vs 20 %. 5 · 6주차 「정격 대비」 와 8주차 「52 기준」 이 섞여 6.8 % 같은 혼선이 생김 → 정의 · 비교 대상(정격, 피크 아님)을 params.yaml 에 고정하고 테스트(test_margin_definition)로 묶음
