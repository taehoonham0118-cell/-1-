# Isaac Lab 핵심 개념 (Core Concepts)

> 1주차 노션 정리본 이전. 1주차 피드백에 따라 개념마다 **B1 활용** 줄과 **수치 기록란**을 붙임.

## 1. Isaac Sim vs Isaac Lab

| | Isaac Sim | Isaac Lab |
|---|---|---|
| 역할 | 물리 시뮬레이션(PhysX), 렌더링, USD 장면 관리 | Sim 위에서 로봇 학습 환경(관측·행동·보상·리셋)을 구성하는 프레임워크 |
| 비유 | 게임 엔진 | 그 엔진으로 만든 훈련장 |

- **B1 활용:** 로봇 모델(USD/URDF)은 Sim이 물리적으로 굴리고, 보행·전신 제어 학습 환경은 Lab으로 만든다.

## 2. 환경 설계 방식 2가지

| | Manager-Based | Direct |
|---|---|---|
| 구조 | 관측·행동·보상·종료·이벤트를 **매니저(설정 클래스)** 단위로 조립 | `step()` 안에 관측·보상 계산을 **직접 코드로** 작성 |
| 장점 | 모듈 재사용·교체 쉬움, 팀 작업에 유리 | 자유도·성능 높음, 복잡한 보상 구현에 유리 |
| 단점 | 구조 이해가 먼저 필요 | 코드가 길어지고 재사용성 낮음 |

- **B1 활용:** 여러 명이 보상·관측 항목을 나눠 실험할 때는 Manager-Based가 유리. 휴머노이드처럼 보상이 복잡하면 Direct도 검토.

## 3. 액추에이터 (Actuator)

- 관절 목표(위치/속도/토크) → 실제 관절 토크로 바꾸는 모델.
- 종류: **Implicit** (PhysX 내부 PD, 빠름) / **Explicit** (IdealPD, DCMotor 등 — Python에서 토크를 계산해 모터 한계를 반영)
- 기본 PD 토크식: `τ = Kp·(q_target − q) + Kd·(q̇_target − q̇)` → 이후 토크·속도 한계로 클리핑
- **B1 활용:** 실제 모터 스펙(정격 토크, 최대 속도)을 액추에이터 설정에 넣어야 sim-to-real 차이가 줄어듦. 하드웨어 서브팀과 ICD로 맞춰야 할 항목.

| 수치 기록란 | 값 | 근거 |
|---|---|---|
| 사용 모터 정격/최대 토크 | | 모터 데이터시트 |
| Kp / Kd | | 튜닝 결과 |

## 4. 센서 5종

| 센서 | 측정 | B1 활용 |
|---|---|---|
| Camera | RGB·깊이·분할 영상 | 인식/시각 기반 정책 |
| Contact Sensor | 접촉 여부·접촉력 | 발 접지 판정, 보행 보상 |
| Frame Transformer | 두 좌표계 간 상대 위치·자세 | 손끝·발끝 위치 계산 |
| IMU | 가속도·각속도·자세 | 몸통 자세 안정화 관측값 |
| Ray Caster | 레이 기반 거리(높이맵) | 지형 인식 |

| 수치 기록란 | 값 | 근거 |
|---|---|---|
| 센서 업데이트 주기 (Hz) | | 설정값 `update_period` |
| 시뮬 dt / decimation | | 환경 설정 |

## 5. 모션 생성기 (Motion Generator)

- 목표 자세 → 관절 명령을 만드는 컨트롤러 (예: 차동 IK, 작업공간 제어).
- **B1 활용:** 팔/상체 목표 위치 추종, 학습 전 기준 동작 검증.
